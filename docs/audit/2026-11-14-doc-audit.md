# Documentation audit, 2026-11-14

Scope: the 17 architecture pages (`docs/architecture/`), the top-level README, `docs/RESEARCH.md`, the research index and sub-indexes (`docs/research/`, 9 folders, about 60 files), and the code they describe (`michel/`, `tests/`). The audit checked four things: coverage (is every requirement and component covered?), staleness (does a page disagree with another page or the code?), accuracy of citations (does a cited source say what the page claims?), and the `[verify]` labels (can they be checked against the installed packages?).

Method: every architecture page was read in full. Code was read in full for `michel/`. Each `[verify]` label was checked against the installed `temporalio` 1.36.0, `temporalio-deepagents` 0.0.3 and `deepagents` 0.7.38 packages. Research citations were grepped in the research notes. Links and stale names were checked by `scripts/check_docs.py`. The test suite was run (22 tests, all pass).

## 6. What the peers changed in the design

Open SWE (now Robin) and T3 Code were read on 2026-11-14 (`docs/research/peers/01-open-swe-and-t3code-structure.md`). They confirmed three patterns that michel already uses or planned: a clear separation between the decision and its side effects, one retained audit table with insert-only rows, and a per-thread sandbox that is never silently replaced. They added five: a typed run catalog (proposed for procedures), tiered settings with sparse overrides, policy read from a pinned or default source (ADR-015), a per-directory rules file (CLAUDE.md), and a single declared configuration registry. Those are recorded above as proposals, not as decisions.
